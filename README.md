# Photo Separator

Отдельный серверный исследовательский стенд для отбора ресторанных обложек. **Android/iOS не изменяются.**

- [Исследование моделей, актуальные цены, архитектура и методика](docs/RESEARCH.ru.md)
- [Результаты pilot и ограничения](docs/PILOT_RESULTS.ru.md)
- [Контракт API и примеры](docs/API.ru.md)
- [20 фотографий двух ресторанов с предварительной разметкой](examples/labeled-pilot.json)

## Быстрый запуск

Требуется Python 3.12+ и [uv](https://docs.astral.sh/uv/).

```bash
uv sync --locked
uv run uvicorn photo_separator.app:app --host 127.0.0.1 --port 8765 --no-access-log
```

Если рядом сохранён локальный runtime первого эксперимента (`data/ollama/`), команда `./scripts/start-local.sh` запускает его на отдельном loopback-порту 11435 вместе со стендом. В чистом clone используйте обычную установку Ollama ниже; runtime/веса в Git не входят.

Открыть **http://127.0.0.1:8765**. Документация API: http://127.0.0.1:8765/docs.

1. Выбрать готовый набор Cremat 11 / «Райский сад» или вставить свои 10 URL.
2. Выбрать провайдера. При облачной модели ввести свой ключ; он остаётся в памяти формы/запроса, не сохраняется в базе или localStorage. Можно использовать серверные env-переменные из `.env.example` (файл автоматически не подхватывается).
3. Нажать «Оценить фотографии». Отдельно видны «взять», «отклонить», «проверить», причины, оценка расходов и выбранные обложки.
4. Повторить с другой моделью: таблица сравнения сохраняется до перезагрузки страницы. API-результаты сохраняются в SQLite и доступны по run ID; адрес `/?run=<id>` восстанавливает отдельный результат после перезагрузки.
5. Сохранить обложку, затем закрепить / исключить фото. Эти решения переживают следующие автоматические прогоны и перезапуск сервера. Исключение убирает фото из обложки, но не удаляет файл на исходном CDN.

Если хороших фото меньше трёх, сервис возвращает меньше трёх. `forward_urls` содержит только выбранные обложки. Ошибка API → `review`, а не случайное принятие.

## Бесплатно локально

Установить Ollama из [официального источника](https://ollama.com/), запустить сервер, скачать модель:

```bash
ollama pull qwen3-vl:8b-instruct
# Компактный baseline для проверки интеграции:
ollama pull qwen3-vl:2b-instruct
# Другие кандидаты, скачиваются только при явном запуске этих команд:
ollama pull qwen3.5:9b
ollama pull gemma4:e4b
ollama pull gemma4:12b
# Для машины с существенно большим запасом памяти:
ollama pull qwen3.8:27b
```

По умолчанию адрес `http://127.0.0.1:11434`. Для своего сервера задайте `OLLAMA_BASE_URL`. Бесплатны веса/вызовы, оборудование и электричество оплачиваются вами. Стенд сам модели не скачивает. **Технический baseline не является ИИ**: он не умеет узнавать меню/людей, отправляет пригодные по размеру файлы на ручную проверку; такой прогон нельзя публиковать как автоматическую обложку.

## Платные API / бесплатная квота

В форме доступны OpenAI Responses, DeepSeek Flash, Gemini через официальный OpenAI-compatible API, Claude Messages, Ollama и собственный OpenAI-compatible endpoint.

Ключи можно передать через `OPENAI_API_KEY`, `DEEPSEEK_API_KEY`, `GEMINI_API_KEY`, `ANTHROPIC_API_KEY`. Не вставляйте ключи в Git/датасет/issue. Gemini free tier требует ключ и доступную квоту; для расчёта бесплатного прогона поставьте тарифы 0 / 0. Для другого облачного провайдера задайте оператором `COMPATIBLE_BASE_URL` и `COMPATIBLE_API_KEY`. В HTTP-запросе нельзя подменять endpoint, на который уйдёт секрет.

`deepseek-flash` поддерживает vision; `deepseek-v4-pro` согласно документации 29.10.2026 — нет. Стенд не подменяет модель при ошибке. Имена моделей и цены редактируемые; проверьте доступность у своего аккаунта.

## Воспроизводимый бенчмарк

```bash
# Без модели: только контроль загрузки/декодирования; содержание не оценивается.
uv run python scripts/benchmark.py --presets technical
# После запуска Ollama и загрузки моделей:
uv run python scripts/benchmark.py --presets qwen2,qwen8
# При настроенных серверных ключах (это платные вызовы или квота аккаунта):
uv run python scripts/benchmark.py --presets deepseek,gpt-luna,gemini
```

Результаты — в `results/pilot/`, фиксированные входные байты — `data/image-cache/`. Скрипт проверяет SHA-256 против manifest; при изменении фото требует обновить выборку. Метки не передаются модели. Точные дубли и слишком маленькие картинки отсеиваются до вызова. Для пользовательского корпуса скопируйте структуру `examples/labeled-pilot.json`, укажите `--dataset`.

Чтобы открыть собственный benchmark в веб-интерфейсе без повторного вызова модели:

```bash
uv run python scripts/import_runs.py results/pilot/qwen8-cremat-11-barcelona.json
```

Команда вернёт локальную ссылку `/?run=...`. Импортируйте только свои сформированные стендом JSON; изображения берутся из фиксированного локального кеша.

Метрики: precision auto-accept и cover, recall, false accept/reject, review-rate, nDCG@6, ошибки, покрытие ≥3 обложками, p50/p95 времени на ресторан и расход. **Разметка pilot предварительная, агентская; не является подтверждённым редакторами gold set.** 20 изображений не доказывают production-точность. Стоимость по usage — оценка по тарифу, а не сверка счёта. На неизвестных тарифах/ошибках показывается неполнота расчёта.

## Проверки

```bash
uv run pytest -q
uv run ruff check photo_separator scripts tests
uv run ruff format --check photo_separator scripts tests
```

Тесты не обращаются к платным API: ответы провайдеров замокированы. Проверяются политика отбора, SSRF/редиректы/DNS pinning, повреждённые изображения, JSON/usage адаптеров, ошибки без утечки ключей, атомарные ручные решения и API. Реальные model runs описаны отдельно.

## Границы стенда

Исследовательский локальный сервис, **не готовый публичный production endpoint**. Нет авторизации, фоновой очереди, автоматического двухмодельного каскада, neural IQA или semantic embeddings. Для production нужны квоты, egress control, бюджеты, мониторинг и интеграция по стабильным photo IDs. Порт 8765 и loopback-адрес являются частью локальной политики Origin; при изменении адреса адаптируйте guard.

База SQLite: `data/workbench.sqlite3`, можно изменить через `PHOTO_DB`. Ключи в ней не сохраняются. База, исходные фото и выгрузки по умолчанию исключены из Git. В репозитории публикуются URL/метки и сводки экспериментов, не сами исходные фотографии.
