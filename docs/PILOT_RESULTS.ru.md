# Реальные результаты pilot: Qwen3-VL 2B против 8B

**29.10.2026. Исторический локальный pilot: 20 исходных фото двух ресторанов пользователя.**

Обновление: после этого выполнены платные GPT/DeepSeek прогоны. Их [результаты](CLOUD_PILOT.ru.md) и общий рейтинг в [README](../README.md) опубликованы отдельно; эта страница сохраняет детали локального эксперимента.

## Практический вывод

**Универсального победителя для автоматической публикации пока нет.** На этой диагностической выборке 8B точнее воспроизводит трёхзначную политику и не теряет пригодный фасад, но пропускает два кадра с людьми на фоне. 2B быстрее и консервативнее, однако путает шкалу оценок, ошибочно отклоняет фасад и тоже пропускает один кадр, требующий проверки.

Для продолжения рабочего pilot я бы взял **8B как помощника редактора**, 2B оставил бы быстрым baseline. Самостоятельно публиковать обложки ни одной из них по этим данным не рекомендую. Следующие бесплатные кандидаты — Gemma 4 E4B/12B, Qwen3.5 9B, на более мощном сервере Qwen3.8 27B. Платные кандидаты для той же выборки — Gemini Flash-Lite, GPT-6 Luna, DeepSeek Flash, Claude Haiku; более дорогой reference — GPT-6.1 Terra/Sol и Claude Sonnet. Это план дальнейшего сравнения, не приписанный им результат.

## Условия фактического теста

- MacBook Pro / Apple M1 Pro / 16 GiB памяти; Ollama **0.40.13**, Metal.
- Qwen3-VL **2B Instruct** и **8B Instruct**; точные digests сохранены в JSON отчётах.
- Один и тот же промпт `restaurant-cover-v1`, одинаковые исходные байты и нормализация до 1280 по длинной стороне.
- Один кадр на модельный запрос, temperature 0, контекст 8192, max prediction 1800, thinking выключен.
- Клиент допускает два вызова одновременно, локальный сервер исполняет один; модели измерялись последовательно.
- Время на ресторан включает подготовку изображений из локального кеша и вызовы модели; скачивание весов в него не входит. Это производительность данного ноутбука, не SLA GPU-сервера.
- Ключи облачных API не настроены. **Расход на API всех выполненных прогонов — $0**, оборудование/энергия не оценивались.

Модель получала изображение и промпт, **без URL, имени файла, alt-текста, ожидаемой метки или описания страницы**. Общая выборка 20 фото → по 20 вызовов каждой модели. Дополнительно 10 кадров Cremat прогнаны через реальный веб-интерфейс с 2B; оценки и решения совпали **10/10**, весь запрос занял 79.783 с с сетевой загрузкой изображений. Это одна проверка повторяемости, не доказательство детерминизма вообще.

## Версии разметки и ограничения

Исходные метки до прогонов сохранены в [labeled-pilot-v1.json](../examples/labeled-pilot-v1.json). После увеличения кадра барной стойки обнаружена ошибка агентской разметки: справа хорошо виден бармен. Метка изменена **keep → review**, grade 3 → 0. Исправленная версия — [labeled-pilot.json, v2](../examples/labeled-pilot.json): **8 keep, 8 reject, 4 review**.

Приведённые ниже цифры пересчитаны **офлайн на тех же предсказаниях**, без повторного вызова моделей. Исходная версия, сырые предсказания, хеши и результаты пересчёта доступны. Такая посткоррекция не превращает выборку в независимый слепой test. Разметка сделана агентом, а не двумя редакторами; 20 специально подобранных фотографий двух ресторанов недостаточно для вывода о production-точности.

## Сравнение по исправленной разметке v2

| Показатель | Technical baseline, без ИИ | Qwen 2B | Qwen 8B |
|---|---:|---:|---:|
| Полное совпадение keep/reject/review | 4/20 | **16/20 (80%)** | **18/20 (90%)** |
| Автоматически принято | 0 | 8 | 10 |
| Из принятых подтверждено меткой keep | — | 7/8 = **87.5%** | 8/10 = **80%** |
| Пропущено кадров с меткой review | 0 | 1 | 2 |
| Автоматически принято явно плохих reject | 0 | **0/8** | **0/8** |
| Найдено из 8 пригодных | 0 | **7/8 = 87.5%** | **8/8 = 100%** |
| Ошибочно отклонено пригодных | 0 | 1 | 0 |
| Отправлено на review | 20 | 1 | 2 |
| nDCG@6 | 0 | 0.8641 | 0.9855 |
| Ошибки HTTP / JSON | 0 | 0 | 0 |
| Обложек Cremat / Райский сад | 0 / 0 | 4 / 4 | 6 / 4 |
| Время на 10 фото, два ресторана | менее 1 с из кеша | **74.563 / 73.168 с** | **187.606 / 194.198 с** |
| Input / output tokens, всего 20 фото | 0 / 0 | **29680 / 6071** | **29680 / 3136** |
| API стоимость | $0 | $0 | $0 |

Важны разные метрики: 8B лучше по полноте и трёхзначной классификации, но **хуже по чистоте автоматически принятых** в данном тесте. Нельзя назвать 90% совпадения меток «90% надёжности обложек»: среди её принятого набора здесь только 80% соответствуют политике keep. У 2B более высокая precision частично достигается лишними отклонениями. Technical baseline не принимает ничего — это безопасно в смысле публикации, но не выполняет задачу самостоятельного отбора.

При столь малом числе принятых фото интервалы неопределённости огромны. Даже нулевой пропуск 8 явно плохих кадров не является свидетельством 99%-ной точности. Ресторанные кластеры коррелируют; показанные в JSON Wilson-интервалы описательные и не учитывают эту зависимость. До production нужен отдельный редакторский корпус и заранее согласованный quality gate, описанный в основном исследовании.

## Что именно пошло не так

**Cremat, фото 1:** на заднем плане за едой видна часть человека. Обе модели выставили `people=none` и автоматически приняли кадр, хотя наша предварительная политика требует review. Это слабое место флага присутствия людей, а не ошибка HTTP или сортировки.

**Cremat, фото 10:** кофе на переднем плане, посетительница на фоне. 8B приняла кадр; 2B отклонила его по низкой числовой оценке, хотя в своём описании назвала фото хорошим. Правильный по нашей политике исход — review. Случайное безопасное отклонение не означает правильного понимания причины.

**Cremat, фото 5:** фасад с небольшой вывеской. 2B сочла текст доминирующим и отклонила; 8B сохранила. Именно такой контрпример нужен против правила «есть текст → плохая фотография».

**Cremat, фото 4:** барная стойка с барменом. Обе модели отправили на review; первичная агентская метка keep была ошибочной и исправлена просмотром оригинала. Это отдельное напоминание о необходимости проверки эталонной разметки.

**Числовая шкала 2B:** в 8 ответах все три оценки не превышают 10 при инструкции 0–100. Часть объяснений при этом положительные, например интерьер с quality=8. Это признак смешения шкал/нестабильной оценки; нельзя автоматически умножать такие числа на десять. У 8B такого наблюдения на этих кадрах нет. Валидный JSON и число в допустимом диапазоне не доказывают смысловую корректность.

**Уверенность:** 2B дала confidence ≥0.95 в 14 из 20 ответов, 8B — **20 из 20**, включая оба нежелательных автоматических принятия. Порог confidence сам по себе не обеспечивает репутационную защиту. Требуется внешняя калибровка и отдельный сигнал для людей/документов или редактор.

**Длина ответа:** 2B расходовала примерно вдвое больше output-токенов, чем 8B, несмотря на меньший размер модели. Фактическое потребление не сводится к параметрам или рекламной цене токена. Токены Qwen нельзя автоматически переносить на OpenAI/Gemini/Claude.

## Что реально проверено в стенде

**42 автоматических теста пройдено**, Ruff и синтаксис JavaScript проверены. Проверяются правила, URL-безопасность и DNS pinning, редиректы, повреждённые/анимированные файлы, реальные image-поля всех адаптеров на mock HTTP, неполные ответы, стоимость, отсутствие ключей в ошибках, сохранение обложек, конфликты revision и ручные исключения. Mock-проверка платного адаптера не означает подтверждённую работоспособность конкретного облачного аккаунта или качество модели.

Через браузер с настоящей 2B проверены полный путь 10 URL → решения → сохранение → pin → exclude → reload → reset. После reload закрепление и исключение сохранились. Исследовательское `cover` API работает локально; production API Restaurant Guru не изменялось. Android/iOS и Gradle не затрагивались.
