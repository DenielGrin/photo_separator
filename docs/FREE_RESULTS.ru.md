# Бесплатное облако: реальные прогоны 29.10.2026

Выполнены реальные image-запросы ко всем **8 моделям** публичного каталога OpenRouter, одновременно удовлетворяющим условиям `:free`, image input и нулевая цена prompt/completion/image/request. Это максимум подходящих моделей данного каталога на момент проверки, а не всех существующих моделей мира. Ключи Gemini/HF не предоставлялись; их inference не проверен.

**Денежный расход аккаунта по `/api/v1/key`: $0.** Финальный счётчик бесплатной квоты: **48 из 50**, остаток **2** оставлен в резерве. Полные наборы по 20 фото получены для Dots и Nano; Super VL успела обработать 13 фото. Проверка endpoint одним фото не является сравнением качества на 20 фото.

## Сравнение двух завершённых бесплатных прогонов

Порядок — сначала меньше сбоев, затем accuracy. Оба варианта исключены из основного рейтинга README по заранее заданному условию «ноль технических ошибок»; хорошие проценты на успешных ответах не скрывают остальные сбои.

| Модель | Чистота выбранных | Найдено хороших | Accuracy | Сбои / 20 | Review | ≥3 обложки / рестораны |
|---|---|---|---|---|---|---|
| Dots 3 Note Preview | 100% (6/6) | 75% (6/8) | 80% | 3 | 40% | 1/2 |
| Nemotron Nano Omni Reasoning | 100% (6/6) | 75% (6/8) | 55% | 7 | 55% | 2/2 |

**Dots перспективнее по стабильности текущего контракта; Nano лучше покрыла оба ресторана минимумом из трёх обложек.** В обоих случаях ноль ошибочных принятий на этом пилоте. При всего шести принятиях нижняя граница Wilson 95% для precision — около **61%**, поэтому измеренные 100% нельзя переносить на production. Разметка составлена агентом, независимо людьми не проверена.

Dots: три ответа не были подтверждены провайдером как завершённые (`finish_reason` не `stop`). Точная причина в старом отчёте не сохранена; нельзя уверенно утверждать, что все они обрезаны именно по лимиту токенов. Nano: один ответ не прошёл схему JSON, шесть отмечены старой общей ошибкой «сетевой сбой или неподдерживаемый ответ». Нельзя считать все семь ошибками зрения модели. Новая диагностика отдельно сохраняет класс сетевой ошибки и безопасный код завершения, без тела ответа и без секретов.

Один запрос Nano долго не завершался; процесс остановлен с сохранением checkpoint. Добавлен общий таймаут 150 секунд на model call поверх сетевых таймаутов. После возобновления ранее полученные ошибки не повторялись и не заменялись удачными ответами. Для одного прерванного запроса результат неизвестен; повторная отправка учтена счётчиком попыток. Гарантии exactly-once billing при прерывании нет.

## Протокол и ограничения

- Те же 20 исходных фото двух ресторанов, байты сверены с manifest SHA-256. Всего 8 keep / 8 reject / 4 review.
- Тот же промпт `restaurant-cover-v1`, нормализация, threshold, правила людей и выбора до шести обложек. Метки модели не передавались.
- Четыре endpoints поддерживают `response_format`; остальные получают контракт JSON в промпте, затем проходят ту же строгую схему.
- Весь ответ ограничен текущим `max_tokens=1800`. Для reasoning-моделей это может быть недостаточно; данное объяснение — гипотеза, не доказанная причина всех ошибок. Следующий эксперимент с большим бюджетом ответа должен иметь отдельный протокол и выходную папку.
- После начальной пробы все доступные модели проходили полный набор по очереди. Это не случайный порядок и не оценка средней доступности разных часов суток.
- Полные данные Dots/Nano включают ошибки как review. Ошибочные фото не исчезают из знаменателя accuracy.
- Частичный Super VL не сравнивается с полными моделями по precision/recall: состав обработанных фото отличается.
- Задержки возобновлённых запусков не сравниваются с локальными или платными тестами. В старых per-photo latency включено ожидание слота; это не чистое время inference.
- Счётчик checkpoint показывает **61 зарезервированную попытку**, OpenRouter — **48 дневных запросов**. Это разные счётчики: попытка фиксируется до отправки; сетевой отказ, отказ endpoint или прерывание не обязательно соответствует засчитанному запросу.

## Воспроизведение и продолжение

```bash
# Просмотр каталога без ключа:
uv run python scripts/benchmark_free.py --plan-only
# Ключ передаётся окружением, не в Git и не аргументом командной строки:
uv run --env-file .env python scripts/benchmark_free.py --max-calls 40
# Обновить опубликованные данные и README:
uv run python scripts/publish_free_results.py
uv run python scripts/update_leaderboard.py
```

После восстановления квоты та же выходная папка продолжит недостающие фото Super VL. Успешные оценки, зафиксированные ошибки и завершённые наборы по умолчанию переиспользуются, без повторной отправки. Для повторной попытки endpoints с 403/429 есть `--retry-unavailable`; для повторения ошибочных ответов — `--retry-errors`. Такие повторы меняют протокол: для формального нового сравнения используйте новую папку `--output`, фиксируйте бюджет, число попыток и политику повторов заранее. При замене наблюдения новая версия checkpoint сохраняет прежнее в `previous_observations`.

Ключ использован только в памяти отдельных процессов; в `.env`, исходники, отчёты и Git не записывался. Все процессы с ключом завершены, временный runner удалён. Исходную историю чата агент удалить не может; опубликованный в чате ключ следует отозвать после использования.
